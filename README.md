## Блок 1 — Цифровые коды. Коды Грея

### Что такое двоичный код и зачем он нужен?

Компьютер понимает только два состояния: ток есть (1) и тока нет (0). Любое число нужно записать через эти два символа. Например, число 5 в двоичном виде — это `101`: одна четвёрка + ноль двоек + одна единица = 5.

Чтобы перевести число в двоичный код, его последовательно делят на 2 и записывают остатки снизу вверх:

```
19 / 2 = 9, остаток 1
 9 / 2 = 4, остаток 1
 4 / 2 = 2, остаток 0
 2 / 2 = 1, остаток 0
 1 / 2 = 0, остаток 1

Читаем снизу вверх: 10011 — это и есть 19 в двоичном виде.
```

---

### Что такое двоично-десятичный код (BCD)?

Обычный двоичный код кодирует всё число целиком. BCD (Binary Coded Decimal) работает иначе: **каждая цифра числа кодируется отдельно** четырьмя битами.

Число **25** в BCD:
- Цифра `2` → `0010`
- Цифра `5` → `0101`
- Итого: `0010 0101`

Зачем это нужно? Например, на калькуляторе или цифровом табло проще отображать каждую цифру по отдельности — не нужно каждый раз переводить всё число обратно в десятичное.

# Зачем нужен код Грея

## Проблема, которую он решает

Представь энкодер — устройство, которое определяет угол поворота вала. Например, в станке, роботе или руле. На диске нарисованы чёрные и белые полосы, а считыватель читает их как 0 и 1.

Вот диск с обычным двоичным кодом:

```
Угол    Код
0°   →  000
45°  →  001
90°  →  010
135° →  011
180° →  100   ← здесь меняются все три бита
```

При переходе `011 → 100` меняются **все три бита одновременно**. Но в реальности считыватель — это три физических сенсора, и они никогда не срабатывают в абсолютно одинаковый момент. Один сенсор чуть быстрее, другой чуть медленнее.

Что происходит в этот момент:

```
Должно быть:  011 → 100
Реально может быть:
  Сначала сработал бит 2:  111 = 7  (ошибка!)
  Потом бит 1:             101 = 5  (ошибка!)
  Потом бит 0:             100 = 4  (верно)
```

За долю секунды прибор показал 7, потом 5, потом правильное 4. Если это станок — он дёрнулся не туда. Если это медицинское оборудование — последствия серьёзнее.

---

## Как код Грея это исправляет

В коде Грея между любыми соседними значениями меняется **ровно один бит**:

```
Угол    Двоичный    Код Грея
0°   →  000      →  000
45°  →  001      →  001
90°  →  010      →  011
135° →  011      →  010
180° →  100      →  110   ← меняется только один бит
```

Теперь при переходе `010 → 110` только один сенсор срабатывает. Промежуточных неверных состояний просто не существует — либо старое значение, либо новое. Ошибка не накапливается.

---

## Где это реально используется

**Энкодеры** — самое массовое применение. Любой сервопривод, шаговый мотор с обратной связью, поворотный джойстик. Код Грея придуман именно для этого.

**АЦП (аналого-цифровые преобразователи)** — когда непрерывный сигнал (напряжение, температура) переводится в число. На границе двух чисел прибор на мгновение находится "между" — код Грея минимизирует ошибку в этот момент.

**Карты Карно** — в цифровой логике при упрощении булевых функций. Ячейки расставляют в порядке кода Грея, чтобы соседние ячейки отличались на один бит — тогда легче находить группы для минимизации.

**Генетические алгоритмы** — когда числа кодируются в битовые строки для "скрещивания". Код Грея уменьшает "скачки" значений при случайных мутациях одного бита.

**Задача Ханойской башни** — последовательность ходов оптимального решения для n дисков совпадает с кодом Грея для чисел от 0 до 2ⁿ−1. Это красивое математическое совпадение, не случайность.

---

## Главная идея одной фразой

Код Грея — это способ пронумеровать состояния так, чтобы физическая ошибка считывания в один бит давала **соседнее** значение, а не случайное. Это делает систему устойчивой к реальным несовершенствам железа.

---

### Как построить код Грея из двоичного числа?

Правило простое, работает слева направо:

1. **Первый бит** кода Грея = первый бит двоичного числа (просто копируем)
2. **Каждый следующий бит** = XOR между текущим и предыдущим битом двоичного числа

**XOR (исключающее ИЛИ)** — операция, которая даёт 1 только если биты **разные**:
```
0 ⊕ 0 = 0
1 ⊕ 1 = 0
0 ⊕ 1 = 1
1 ⊕ 0 = 1
```

**Пример: число 11 → двоичный 01011**
```
g1 = b1 = 0
g2 = b1 ⊕ b2 = 0 ⊕ 1 = 1
g3 = b2 ⊕ b3 = 1 ⊕ 0 = 1
g4 = b3 ⊕ b4 = 0 ⊕ 1 = 1
g5 = b4 ⊕ b5 = 1 ⊕ 1 = 0

Код Грея: 01110
```

---

### Как перевести обратно из кода Грея в двоичный?

Почти то же самое, только теперь XOR берётся между **предыдущим битом двоичного** и **текущим битом Грея**:

1. **Первый бит** двоичного = первый бит кода Грея
2. **Каждый следующий**: b_i = b_(i-1) ⊕ g_i

**Пример: код Грея 01110 → обратно**
```
b1 = g1 = 0
b2 = b1 ⊕ g2 = 0 ⊕ 1 = 1
b3 = b2 ⊕ g3 = 1 ⊕ 1 = 0
b4 = b3 ⊕ g4 = 0 ⊕ 1 = 1
b5 = b4 ⊕ g5 = 1 ⊕ 0 = 1

Двоичный: 01011 = 11 ✓
```

## Часть 1. Матрицы и системы уравнений

### Что такое матрица

Матрица — это просто таблица чисел. Ничего страшного. Например, матрица 2×2:

```
A = | 2  1 |
    | 3 -1 |
```

Матрицы нужны, чтобы компактно записывать системы уравнений. Вот система:

```
2x + y  = 5
3x - y  = 4
```

Её можно записать в матричном виде **A · X = B**, где:

```
A = | 2  1 |      X = | x |      B = | 5 |
    | 3 -1 |          | y |          | 4 |
```

Умножение A на X даёт ровно те же уравнения — просто записано компактнее.

---

### Как работает умножение матриц

Умножение матриц — не просто поэлементное умножение. Правило такое: **строка на столбец**.

Элемент результата в позиции (i, j) — это сумма произведений i-й строки первой матрицы на j-й столбец второй.

Пример: A · X

```
| 2  1 |   | x |   | 2·x + 1·y |   | 2x + y |
| 3 -1 | · | y | = | 3·x - 1·y | = | 3x - y |
```

Это в точности и есть наша система уравнений. Вот зачем нужно матричное умножение.

---

### Определитель матрицы — что это и зачем

Определитель (det) — это одно число, которое вычисляется из матрицы и говорит о ней много важного.

Для матрицы 2×2 формула простая:

```
A = | a  b |
    | c  d |

det(A) = a·d - b·c
```

Пример:

```
A = | 2  1 |
    | 3 -1 |

det(A) = 2·(-1) - 1·3 = -2 - 3 = -5
```

**Зачем проверять определитель перед решением?**

Если `det(A) = 0` — система либо не имеет решений, либо имеет бесконечно много. Обратной матрицы не существует, и формула X = A⁻¹ · B просто не работает. Это как деление на ноль — математически запрещено.

Если `det(A) ≠ 0` — всё хорошо, решение единственное.

Геометрический смысл: определитель — это площадь параллелограмма, построенного на столбцах матрицы. Если он равен нулю — столбцы параллельны, то есть уравнения системы зависимы (одно является следствием другого).

---

### Обратная матрица

Обратная матрица A⁻¹ — такая, что:

```
A · A⁻¹ = E

где E = | 1  0 |  — единичная матрица (аналог числа 1 для матриц)
        | 0  1 |
```

Для матрицы 2×2 формула:

```
A = | a  b |          A⁻¹ =  1/det(A) · | d  -b |
    | c  d |                              | -c  a |
```

То есть: меняем элементы на главной диагонали, меняем знаки на побочной, делим всё на определитель.

Для матриц большего размера (3×3, 4×4) формула сложнее — там используются миноры и алгебраические дополнения. В MathCad это делается автоматически оператором `A⁻¹`, вычислять вручную не нужно.

---

### Решение системы

Имея обратную матрицу, решение получается умножением:

```
A · X = B
A⁻¹ · A · X = A⁻¹ · B
E · X = A⁻¹ · B
X = A⁻¹ · B
```

В MathCad это три строки:

```
D := det(A)     ← убеждаемся, что D ≠ 0
C := A⁻¹        ← MathCad сам считает обратную матрицу
X := C · B      ← получаем вектор решений
```

**Проверка:** умножаем A · X и сравниваем с B. Если совпало — всё верно.

## Часть 2. Корни полинома

### Что такое полином

Полином (многочлен) — выражение вида:

```
P(x) = aₙxⁿ + aₙ₋₁xⁿ⁻¹ + ... + a₁x + a₀
```

Корень полинома — значение x, при котором P(x) = 0.

Для полинома степени n существует ровно n корней (с учётом кратных и комплексных) — это основная теорема алгебры.

---

### Почему корни бывают комплексными

Возьмём простой пример: `x² + 1 = 0`

```
x² = -1
x  = √(-1)  ← квадратный корень из отрицательного числа
```

В обычных (вещественных) числах этого не существует. Но математики ввели число `i = √(-1)` и назвали его **мнимой единицей**. Тогда:

```
x = ±i
```

Комплексное число — это `a + bi`, где a — вещественная часть, b — мнимая. Примеры:
- `3 + 2i` — комплексное число
- `-0.103 + 2.116i` — тоже комплексное
- `2.68 + 0i = 2.68` — обычное вещественное число (мнимая часть = 0)

Комплексные корни всегда приходят **парами**: если `a + bi` — корень, то `a - bi` тоже корень. Это называется комплексно-сопряжённая пара.

---

### Как MathCad находит корни: функция polyroots

`polyroots(p)` — численный метод нахождения всех корней полинома.

Вектор `p` задаётся **от младшей степени к старшей**:

```
Полином: 3 + x + 8x² + 4x³ + x⁴ + 2x⁵

p = | 3 |  ← свободный член (x⁰)
    | 1 |  ← коэффициент при x¹
    | 8 |  ← коэффициент при x²
    | 4 |  ← коэффициент при x³
    | 1 |  ← коэффициент при x⁴
    | 2 |  ← коэффициент при x⁵
```
> ВАЖНО! На рисунке в примере используется вектор-строка для удобства, с оператором транспонирования (он переворачивает вектор и делает вектор-столбец) это все для удобства, так проще на вид воспринимать информацию

Это частая ошибка — люди пишут коэффициенты от старшей к младшей, как привыкли в учебнике. В `polyroots` нужно наоборот.

---

### Сортировка корней: функция csort

`csort(r, 0)` сортирует вектор r по возрастанию значений в столбце 0.

Для комплексных чисел "столбец 0" — это вещественная часть (Re). Поэтому корни расставляются по возрастанию их вещественной части:

```
До сортировки:   2.68, -0.492, 0.259+0.432i, 0.259-0.432i, ...
После csort:     -0.492, -0.103+2.116i, -0.103-2.116i, 0.259-0.432i, ...
```

## Часть 3. Аппроксимация данных

### Зачем нужна аппроксимация

У вас есть 10 точек из эксперимента. Вы хотите:
1. Построить плавную кривую через них
2. Узнать значение в любой промежуточной точке (например, при x = 2.15)
3. Понять общую тенденцию зависимости

Просто соединить точки прямыми линиями — грубо, на изломах кривая "ломается". Нужна математически гладкая кривая.

---

### Что такое кубический сплайн

Сплайн — кривая, которая строится по частям. Между каждыми двумя соседними точками прокладывается отдельный кубический полином (степени 3).

Почему кубический? Потому что кубический полином имеет достаточно параметров, чтобы:
- Пройти через обе точки (2 условия)
- Совпасть по наклону с соседними кусками на стыках (непрерывность первой производной)
- Совпасть по кривизне на стыках (непрерывность второй производной)

Это и обеспечивает гладкость — никаких углов и переломов.

---

### Формулы и функции MathCad

**Шаг 1: вычислить коэффициенты сплайна**

```
vs := cspline(xd, yd)
```

`cspline` берёт векторы x и y, решает систему уравнений для нахождения вторых производных в каждой точке (отсюда и гладкость), и возвращает вспомогательный вектор `vs`. Этот вектор — не значения функции, а служебные коэффициенты для дальнейшего вычисления.

**Шаг 2: задать плотную сетку точек для гладкой кривой**

```
t := min(xd), min(xd) + 0.05 .. max(xd)
```

Это переменная диапазона — она принимает значения от минимального x до максимального с шагом 0.05. Чем меньше шаг, тем плавнее выглядит кривая на графике.

**Шаг 3: вычислить значения сплайна в каждой точке t**

```
y(t) := interp(vs, xd, yd, t)
```

`interp` использует коэффициенты `vs` и исходные данные, чтобы вычислить значение сплайна в произвольной точке t. Внутри она определяет, между какими двумя узлами находится t, берёт нужный кубический полином и считает результат.

---

### Почему сплайн "скачет" при резких данных

Если данные резко меняются — например, y = 4.5 при x = 2.5, а y = 1.3 при x = 2.6 — сплайн вынужден резко упасть на этом участке. Но условие гладкости требует плавного входа и выхода из этого падения, поэтому кривая немного "проваливается" перед резким участком и "подпрыгивает" после него.

Это не ошибка метода — это математическое следствие требования гладкости. Явление называется **эффектом Рунге**. Если данные очень неравномерные, иногда лучше использовать аппроксимацию (МНК), которая не обязана проходить точно через каждую точку, зато не скачет.

---

### Разница между интерполяцией и аппроксимацией

| | Интерполяция (сплайн) | Аппроксимация (МНК) |
|---|---|---|
| Проходит через точки | Точно через все | Не обязательно |
| Поведение между точками | Может скакать | Плавная общая тенденция |
| Когда использовать | Данные точные, без шума | Данные с погрешностью измерений |

В MathCad для МНК (метод наименьших квадратов) используется функция `linfit` или `expfit` в зависимости от формы зависимости.

## Блок 3 — Алгоритмы и язык C++

### Что такое алгоритм и блок-схема?

Алгоритм — это точная последовательность шагов для решения задачи. Ключевое слово — **точная**: компьютер делает ровно то, что написано, и не додумывает.

Блок-схема — визуальное представление алгоритма. Каждый тип действия имеет свою форму:

| Фигура | Что означает |
|--------|-------------|
| Овал | Начало / Конец |
| Параллелограмм | Ввод или вывод данных |
| Прямоугольник | Вычисление / действие |
| Ромб | Условие (да/нет) |

---

### Задача 1: Часовая стрелка

Часовая стрелка делает полный круг (360°) за 12 часов. Значит, за 1 час она поворачивается на 360° / 12 = **30°**.

Если стрелка повернулась на `f` градусов, то прошло `h = f / 30` часов.

**Главная ловушка в коде** — целочисленное деление. В C++:
```cpp
int f = 90;
int h = f / 30;   // h = 3 — работает, но...

int f = 45;
int h = f / 30;   // h = 1, а не 1.5 — дробная часть потеряна!
```

Правильно объявить `f` как `double` и делить на `30.0`:
```cpp
double f = 45.0;
double h = f / 30.0;   // h = 1.5 ✓
```

### Задача 2: Рабочий день

Здесь нужно по номеру дня года узнать, какой это день недели и какая неделя. Люди часто путаются в формулах — разберём по шагам.

**День недели** (1 = понедельник, 7 = воскресенье):
```
dayOfWeek = (k - 1) % 7 + 1
```
Зачем вычитать 1? Чтобы первый день (k=1) дал остаток 0, а не 1. Тогда +1 в конце даёт ровно 1 (понедельник). Без вычитания k=7 дало бы остаток 0 — это был бы понедельник вместо воскресенья.

**Номер недели:**
```
weekNum = (k - 1) / 7 + 1
```
Целочисленное деление автоматически отбрасывает дробную часть — именно это и нужно.

**Условие "рабочий день"** — оба условия должны выполняться **одновременно**:
```cpp
bool isWorking = (dayOfWeek % 2 == 0) && (weekNum % 2 == 0);
```
Оператор `&&` — это "И": если хоть одно условие ложно, всё выражение ложно.

### Задача 3: Битовые операции

Числа в компьютере хранятся в виде бит. Число 170 в 8-битном виде: `10101010`. Иногда нужно работать напрямую с отдельными битами — не с числом целиком.

**Три главных битовых оператора:**

| Оператор | Символ | Что делает |
|----------|--------|------------|
| AND | `&` | Бит равен 1, только если оба бита = 1 |
| OR | `\|` | Бит равен 1, если хотя бы один бит = 1 |
| Сдвиг влево | `<<` | Сдвигает все биты на N позиций влево |

**Как оставить только i-й и j-й биты?**

Шаг 1 — создать маску: число, где стоят 1 только на нужных позициях:
```cpp
int mask = (1 << i) | (1 << j);
```
`1 << 3` означает "1, сдвинутая на 3 позиции" → `00001000` (8 в десятичном)

Шаг 2 — применить маску через AND:
```cpp
int result = k & mask;
```
Там, где маска = 1, бит числа **сохраняется**. Там, где маска = 0, бит **обнуляется**.

**Конкретный пример** (k = 170, i = 1, j = 3):
```
k    = 10101010
mask = 00001010  (биты 1 и 3)
─────────────────
AND  = 00001010  = 10
```

**Как вывести число в двоичном виде?** В C++ нет встроенной функции для этого, поэтому берём каждый бит вручную:
```cpp
for (int b = 7; b >= 0; b--) {
    cout << ((k >> b) & 1);
}
```
`(k >> b) & 1` — сдвигаем нужный бит на нулевую позицию, затем отрезаем все остальные через AND с 1.
