## Блок 1 — Цифровые коды. Коды Грея

### Что такое двоичный код и зачем он нужен?

Компьютер понимает только два состояния: ток есть (1) и тока нет (0). Любое число нужно записать через эти два символа. Например, число 5 в двоичном виде — это `101`: одна четвёрка + ноль двоек + одна единица = 5.

Чтобы перевести число в двоичный код, его последовательно делят на 2 и записывают остатки снизу вверх:

```
19 / 2 = 9, остаток 1
 9 / 2 = 4, остаток 1
 4 / 2 = 2, остаток 0
 2 / 2 = 1, остаток 0
 1 / 2 = 0, остаток 1

Читаем снизу вверх: 10011 — это и есть 19 в двоичном виде.
```

---

### Что такое двоично-десятичный код (BCD)?

Обычный двоичный код кодирует всё число целиком. BCD (Binary Coded Decimal) работает иначе: **каждая цифра числа кодируется отдельно** четырьмя битами.

Число **25** в BCD:
- Цифра `2` → `0010`
- Цифра `5` → `0101`
- Итого: `0010 0101`

Зачем это нужно? Например, на калькуляторе или цифровом табло проще отображать каждую цифру по отдельности — не нужно каждый раз переводить всё число обратно в десятичное.

---

### Код Грея — в чём фокус?

Представьте, что у вас есть линейка с делениями, и вы считываете положение указателя. При переходе с одного деления на другое считыватель может "поймать" момент, когда часть бит уже изменилась, а часть — нет. Получается мусор.

**Пример с обычным двоичным кодом:**
```
15 = 01111
16 = 10000
```
При переходе 15 → 16 меняются **все 5 бит** одновременно. Если считыватель успел прочитать старший бит от 16, а остальные — от 15, получится:
```
0|0000 = 00000 = 0
```
Вместо 15 или 16 прибор показывает **0** — ошибка в 15 единиц!

**Код Грея решает эту проблему.** Его главное свойство: при переходе между любыми двумя соседними числами изменяется **ровно один бит**. Неважно, какой переход — 3→4, 15→16, 31→0 — всегда один бит.

Значит, даже если считыватель поймал "плохой" момент, он прочитает либо текущее значение, либо соседнее. Ошибка — максимум 1 единица, а не 15.

---

### Как построить код Грея из двоичного числа?

Правило простое, работает слева направо:

1. **Первый бит** кода Грея = первый бит двоичного числа (просто копируем)
2. **Каждый следующий бит** = XOR между текущим и предыдущим битом двоичного числа

**XOR (исключающее ИЛИ)** — операция, которая даёт 1 только если биты **разные**:
```
0 ⊕ 0 = 0
1 ⊕ 1 = 0
0 ⊕ 1 = 1
1 ⊕ 0 = 1
```

**Пример: число 11 → двоичный 01011**
```
g1 = b1 = 0
g2 = b1 ⊕ b2 = 0 ⊕ 1 = 1
g3 = b2 ⊕ b3 = 1 ⊕ 0 = 1
g4 = b3 ⊕ b4 = 0 ⊕ 1 = 1
g5 = b4 ⊕ b5 = 1 ⊕ 1 = 0

Код Грея: 01110
```

---

### Как перевести обратно из кода Грея в двоичный?

Почти то же самое, только теперь XOR берётся между **предыдущим битом двоичного** и **текущим битом Грея**:

1. **Первый бит** двоичного = первый бит кода Грея
2. **Каждый следующий**: b_i = b_(i-1) ⊕ g_i

**Пример: код Грея 01110 → обратно**
```
b1 = g1 = 0
b2 = b1 ⊕ g2 = 0 ⊕ 1 = 1
b3 = b2 ⊕ g3 = 1 ⊕ 1 = 0
b4 = b3 ⊕ g4 = 0 ⊕ 1 = 1
b5 = b4 ⊕ g5 = 1 ⊕ 0 = 1

Двоичный: 01011 = 11 ✓
```

## Блок 2 — Работа в MathCad

### Что такое MathCad и чем он отличается от обычного кода?

В обычном языке программирования (Python, C++) вы пишете команды: "сложи это, раздели то, запиши в переменную". MathCad устроен иначе — вы **пишете математику так, как она выглядит в учебнике**, и система сразу считает.

Написали `X := A⁻¹ · B` — получили решение системы уравнений. Никаких циклов, никаких явных алгоритмов. Это называется **символьно-числовая среда**.

---

### Матрицы и решение систем уравнений

Система уравнений — это когда несколько переменных связаны между собой:
```
2x + y - z = 3
x - 3y + 2z = -1
...
```

Это можно записать компактно в матричном виде: **A · X = B**, где:
- **A** — таблица коэффициентов при переменных
- **X** — столбец с неизвестными (что ищем)
- **B** — столбец свободных членов (правая часть уравнений)

Чтобы найти X, нужно "разделить" обе части на A. Деления матриц не существует, но есть **обратная матрица** A⁻¹ — такая, что A · A⁻¹ = E (единичная матрица, аналог единицы для матриц). Тогда:
```
X = A⁻¹ · B
```

**Почему сначала считают определитель?**
Если `det(A) = 0`, обратной матрицы не существует — система либо не имеет решений, либо имеет бесконечно много. Если `det(A) ≠ 0` — решение единственное, и можно смело считать.

В MathCad это делается тремя строками:
```
D := det(A)        ← проверяем, что ≠ 0
C := A⁻¹           ← находим обратную матрицу
X := C · B         ← получаем решение
```

### Корни полинома

Полином — это выражение вида `aₙxⁿ + ... + a₁x + a₀`. Корни — это значения x, при которых полином равен нулю.

Для полинома степени 2 есть формула с дискриминантом. Для степени 3 — более сложная. Для степени 5 и выше — аналитической формулы вообще не существует, нужны численные методы.

MathCad решает это функцией `polyroots(p)`, где `p` — вектор коэффициентов **от младшей степени к старшей**:
```
Полином: 2x⁵ + x⁴ + 4x³ + 8x² + x + 3
Вектор: p = [3, 1, 8, 4, 1, 2]  ← сначала свободный член, потом x¹, x², ...
```

**Почему корни могут быть комплексными?**
Комплексное число — это число вида `a + bi`, где `i = √(−1)`. Уравнение x² + 1 = 0 в обычных числах решений не имеет, но в комплексных — имеет: x = ±i. По основной теореме алгебры, полином степени n всегда имеет ровно n корней — но часть из них может быть комплексными. Это нормально.

### Аппроксимация и сплайны

Допустим, вы провели эксперимент и получили 10 точек. Нужно описать зависимость плавной кривой — так, чтобы можно было предсказать значения между точками.

**Аппроксимация** — построение кривой, которая описывает данные (не обязательно проходит точно через каждую точку).

**Интерполяция** — кривая, которая проходит **точно через каждую точку**.

**Кубический сплайн** — это интерполяция, при которой кривая на каждом участке между двумя точками описывается кубическим полиномом. Условия стыковки между участками обеспечивают гладкость (без углов и переломов).

В MathCad:
```
vs := cspline(xd, yd)      ← считаем коэффициенты сплайна
y(t) := interp(vs, xd, yd, t)  ← получаем значение в любой точке t
```

**Почему сплайн "прыгает" при резких данных?**
Если соседние точки резко отличаются по значению (например, 4.5 и 1.3 при шаге 0.1 по x), сплайн вынужден "нырнуть" вниз и потом подняться — это математическое следствие требования гладкости. Это не ошибка, а особенность метода.

## Блок 3 — Алгоритмы и язык C++

### Что такое алгоритм и блок-схема?

Алгоритм — это точная последовательность шагов для решения задачи. Ключевое слово — **точная**: компьютер делает ровно то, что написано, и не додумывает.

Блок-схема — визуальное представление алгоритма. Каждый тип действия имеет свою форму:

| Фигура | Что означает |
|--------|-------------|
| Овал | Начало / Конец |
| Параллелограмм | Ввод или вывод данных |
| Прямоугольник | Вычисление / действие |
| Ромб | Условие (да/нет) |

---

### Задача 1: Часовая стрелка

Часовая стрелка делает полный круг (360°) за 12 часов. Значит, за 1 час она поворачивается на 360° / 12 = **30°**.

Если стрелка повернулась на `f` градусов, то прошло `h = f / 30` часов.

**Главная ловушка в коде** — целочисленное деление. В C++:
```cpp
int f = 90;
int h = f / 30;   // h = 3 — работает, но...

int f = 45;
int h = f / 30;   // h = 1, а не 1.5 — дробная часть потеряна!
```

Правильно объявить `f` как `double` и делить на `30.0`:
```cpp
double f = 45.0;
double h = f / 30.0;   // h = 1.5 ✓
```

### Задача 2: Рабочий день

Здесь нужно по номеру дня года узнать, какой это день недели и какая неделя. Люди часто путаются в формулах — разберём по шагам.

**День недели** (1 = понедельник, 7 = воскресенье):
```
dayOfWeek = (k - 1) % 7 + 1
```
Зачем вычитать 1? Чтобы первый день (k=1) дал остаток 0, а не 1. Тогда +1 в конце даёт ровно 1 (понедельник). Без вычитания k=7 дало бы остаток 0 — это был бы понедельник вместо воскресенья.

**Номер недели:**
```
weekNum = (k - 1) / 7 + 1
```
Целочисленное деление автоматически отбрасывает дробную часть — именно это и нужно.

**Условие "рабочий день"** — оба условия должны выполняться **одновременно**:
```cpp
bool isWorking = (dayOfWeek % 2 == 0) && (weekNum % 2 == 0);
```
Оператор `&&` — это "И": если хоть одно условие ложно, всё выражение ложно.

### Задача 3: Битовые операции

Числа в компьютере хранятся в виде бит. Число 170 в 8-битном виде: `10101010`. Иногда нужно работать напрямую с отдельными битами — не с числом целиком.

**Три главных битовых оператора:**

| Оператор | Символ | Что делает |
|----------|--------|------------|
| AND | `&` | Бит равен 1, только если оба бита = 1 |
| OR | `\|` | Бит равен 1, если хотя бы один бит = 1 |
| Сдвиг влево | `<<` | Сдвигает все биты на N позиций влево |

**Как оставить только i-й и j-й биты?**

Шаг 1 — создать маску: число, где стоят 1 только на нужных позициях:
```cpp
int mask = (1 << i) | (1 << j);
```
`1 << 3` означает "1, сдвинутая на 3 позиции" → `00001000` (8 в десятичном)

Шаг 2 — применить маску через AND:
```cpp
int result = k & mask;
```
Там, где маска = 1, бит числа **сохраняется**. Там, где маска = 0, бит **обнуляется**.

**Конкретный пример** (k = 170, i = 1, j = 3):
```
k    = 10101010
mask = 00001010  (биты 1 и 3)
─────────────────
AND  = 00001010  = 10
```

**Как вывести число в двоичном виде?** В C++ нет встроенной функции для этого, поэтому берём каждый бит вручную:
```cpp
for (int b = 7; b >= 0; b--) {
    cout << ((k >> b) & 1);
}
```
`(k >> b) & 1` — сдвигаем нужный бит на нулевую позицию, затем отрезаем все остальные через AND с 1.
